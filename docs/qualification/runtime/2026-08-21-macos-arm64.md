An intentionally wrong required version failed before project validation or
server startup. The direct handler rejects an unknown Handler Protocol version
without writing a response.

Tachyon's current direct executable path receives one bounded plain JSON
request through stdin and writes one plain JSON response through stdout. The
length-prefixed framing described by Handler Protocol v1 applies to supervised
built-in adapters; `direct.v1` is the deliberately simpler one-request process
contract. This behavior is documented on the
[Tachyon site](https://tachyon.del.ma/docs/polyglot) and in the
[current direct-handler implementation](https://github.com/d31ma/Tachyon/blob/f96c1589ee33b047044f220448268d32ad86e58f/crates/tachyon-core/src/handler/process.rs).

## Fylo evidence

The side-effect-free `fylo version --output json` report declared:

- protocol version `1`;
- NDJSON, UTF-8, LF-delimited machine framing;
- maximum request and response frames of 1 MiB and 8 MiB;
- `handshake: true`;
- `exclusiveRoot: true`;
- query pagination v1;
- document buckets v1;
- serverless queue v1; and
- machine access v1.

The focused supervisor then launched this exact argument vector without a
shell:

```text
fylo exec --loop --root <canonical-root> --exclusive-root \
  --max-request-bytes 1048576 --max-response-bytes 8388608
```

It completed a live handshake, started a contender against the same canonical
root, observed Fylo's stable `EROOTLOCKED` response, and confirmed the first
owner remained responsive. Closing stdin released the lease; the same
supervisor reopened and handshook successfully.

Wrong runtime, protocol, and serverless-queue capability requirements all
failed during `fylo version --output json` preflight. In each case the intended
state-root path remained absent. Fylo's handshake request currently ignores an
input `protocolVersion` field and reports its own actual protocol version, so
Sluice compares the returned envelope and result itself rather than assuming
the runtime negotiated the caller's value.

Fylo's own release contract for this behavior is visible in its
[native root-lease test](https://github.com/d31ma/FYLO/blob/e236162508f6789f980fa7ca136a6671938030cb/tests/interop/native-release-root-lease.test.js).

## Remaining dependency gap

The Fylo 26.33.02 binary implements effective exclusive-root ownership, but
the version-matched released Go shim does not expose an option that appends
`--exclusive-root`. Its `OpenWithOptions` argument vector omits the flag in
[clients/go/fylo.go](https://github.com/d31ma/FYLO/blob/e236162508f6789f980fa7ca136a6671938030cb/clients/go/fylo.go).
The shim is distributed as a version-matched vendorable file and has no
standalone versioned Go module (`go list -m
github.com/d31ma/FYLO/clients/go@latest` reports no matching versions).

Sluice therefore uses the focused stdlib supervisor in `internal/state/fylo`.
It supplies the missing flag, performs stricter preflight and live identity
checks, bounds frames, and owns clean lifecycle behavior. Adopting the upstream
Go shim remains prohibited until a version-matched release exposes and tests
the exclusive-root option.
