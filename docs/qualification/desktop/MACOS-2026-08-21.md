## Results

### Unit and race suites

These packages passed both ordinary and race-enabled tests:

```text
./internal/platform/autostart
./cmd/sluice-desktop
./ui/app
```

The focused golangci-lint run for the same packages completed with zero
issues.

### LaunchAgent lifecycle

An amd64 desktop binary was built and executed under an isolated temporary
home. The observable sequence was:

```text
autostart status  -> disabled
autostart enable  -> enabled
autostart status  -> enabled
plutil -lint      -> OK
autostart disable -> disabled
autostart status  -> disabled
```

The test did not place a file in the operator's real `~/Library/LaunchAgents`
directory and did not log out. It therefore qualifies registration creation,
inspection, XML validity, and removal, but not loading by `launchd` at a real
login.

### Native arm64 Fyne lifecycle

The desktop command was cross-built from the amd64 Go host toolchain with:

```text
GOOS=darwin GOARCH=arm64 CGO_ENABLED=1 go build ./cmd/sluice-desktop
```

`file` identified the result as a Mach-O 64-bit arm64 executable. That arm64
artifact ran on the Apple M4 host with `--native-smoke` and exited zero. The
run produced no Fyne runtime error or threading-migration warning. The executed
path created the native Fyne app and system-tray integration, opened the shared
window, hid and showed it, dispatched a notification, and requested a clean
quit.

This automated result does not assert pixels on screen. Visual confirmation
of the tray icon and notification, notification-permission behavior,
VoiceOver, keyboard access, and actual window-close behavior during a live
sync remain open.

### Unsigned packaged process topology

An isolated unsigned arm64 `Sluice.app` was staged with `sluice-desktop`,
`sluice-agent`, `sluice-yon`, pinned Tachyon/Fylo 26.33.02 runtimes, the minimal
Yon health route, and required license notices. With `PATH` restricted to
`/usr/bin:/bin`, the packaged desktop ran twice against one private temporary
state root. Each run:

- resolved helpers and runtimes only from the app bundle;
- started the agent on a private Unix-domain socket and waited for its fresh
  descriptor;
- started Tachyon and returned authenticated `GET /v1/health` status `ok`;
- exercised the bounded Fyne native smoke lifecycle; and
- stopped Tachyon, the agent, and Fylo, then removed the descriptor and socket.

The API token remained stable across the restart and no packaged child process
survived desktop shutdown. The full observations and command are recorded in
`../runtime/2026-08-21-macos-arm64-app.md`.

### Maintained lifecycle and fault recovery

`make app-runtime-qualify-macos` then ran the unsigned packaged topology as a
maintained background application. Authenticated health was ready in 869 ms.
After a 30-second warmup with no recovery, the same four-process generation
remained present for every one of 61 samples over 600 seconds. Aggregate CPU
from process time was 0.855%, all-process RSS averaged 106,599 KiB and peaked
at 186,256 KiB, and clean shutdown completed in 59 ms.

Supervisor recovery was forced only after the sustained sample. The desktop
survived a Tachyon `TERM` and restored authenticated health in 480 ms, then
survived an agent `KILL` and restored health in 372 ms. Each recovery replaced
the complete agent/Tachyon/Fylo generation and rotated the private IPC
capability while preserving the API token and Fylo root. The detailed resource
breakdown is recorded in `../performance/2026-08-21-macos.md`.

### Cross-build observations

- A Windows amd64 desktop artifact built successfully with CGO enabled and Zig
  targeting `x86_64-windows-gnu`; `file` identified a PE32+ x86-64 executable.
- Windows and Linux autostart test binaries cross-built with `CGO_ENABLED=0`;
  `file` identified PE32+ x86-64 and static ELF x86-64 artifacts.
- A full Linux Fyne cross-build did not complete on this host because the
  target sysroot lacks `wayland-client-core.h` and `gl.pc`. This is a local
  cross-toolchain gap, not native Linux evidence and not a Linux runtime
  defect determination.

## Conclusion

The macOS executable, maintained unsigned topology, bounded recovery,
coordinated process shutdown, resource baseline, and isolated registration code
have meaningful native Phase 1 evidence, but macOS has not passed the complete
native spike gate. Visual tray and notification observation, a real-login
LaunchAgent run, and accessibility remain open. Windows is buildable only.
Linux autostart code is buildable only, and the full desktop cross-build still
needs a configured target graphics sysroot. No support or release-tier
promotion is warranted by this record.
