## Results

### Unit and race suites

These packages passed both ordinary and race-enabled tests:

```text
./internal/platform/autostart
./cmd/sluice-desktop
./ui/app
```

The focused golangci-lint run for the same packages completed with zero
issues.

### LaunchAgent lifecycle

An amd64 desktop binary was built and executed under an isolated temporary
home. The observable sequence was:

```text
autostart status  -> disabled
autostart enable  -> enabled
autostart status  -> enabled
plutil -lint      -> OK
autostart disable -> disabled
autostart status  -> disabled
```

The test did not place a file in the operator's real `~/Library/LaunchAgents`
directory and did not log out. It therefore qualifies registration creation,
inspection, XML validity, and removal, but not loading by `launchd` at a real
login.

### Native arm64 Fyne lifecycle

The desktop command was cross-built from the amd64 Go host toolchain with:

```text
GOOS=darwin GOARCH=arm64 CGO_ENABLED=1 go build ./cmd/sluice-desktop
```

`file` identified the result as a Mach-O 64-bit arm64 executable. That arm64
artifact ran on the Apple M4 host with `--native-smoke` and exited zero. The
run produced no Fyne runtime error or threading-migration warning. The executed
path created the native Fyne app and system-tray integration, opened the shared
window, hid and showed it, dispatched a notification, and requested a clean
quit.

This automated result does not assert pixels on screen. Visual confirmation
of the tray icon and notification, notification-permission behavior,
VoiceOver, keyboard access, actual window-close behavior during a live sync,
and coordinated shutdown of the real agent remain open.

### Cross-build observations

- A Windows amd64 desktop artifact built successfully with CGO enabled and Zig
  targeting `x86_64-windows-gnu`; `file` identified a PE32+ x86-64 executable.
- Windows and Linux autostart test binaries cross-built with `CGO_ENABLED=0`;
  `file` identified PE32+ x86-64 and static ELF x86-64 artifacts.
- A full Linux Fyne cross-build did not complete on this host because the
  target sysroot lacks `wayland-client-core.h` and `gl.pc`. This is a local
  cross-toolchain gap, not native Linux evidence and not a Linux runtime
  defect determination.

## Conclusion

The macOS executable and registration code have meaningful native Phase 1
evidence, but macOS has not passed the complete native spike gate. Windows is
buildable only. Linux autostart code is buildable only, and the full desktop
cross-build still needs a configured target graphics sysroot. No support or
release-tier promotion is warranted by this record.
