# Performance baseline: macOS, 2026-08-21

This record establishes the Phase 1 microbenchmark budgets and the maintained
native packaged-process baseline. It is reference-host evidence only, not
evidence for another architecture or operating system.

## Environment

| Item | Value |
| --- | --- |
| Host | macOS 26.5.2 (25F84), Apple Silicon |
| Go execution | Go 1.27.0, `darwin/amd64` under translation |
| Reported CPU | `VirtualApple @ 2.50GHz`, 10 logical CPUs |
| Install filesystem | APFS temporary directory |
| Benchmark duration | 1 second, 5 independent samples |

The translated Go architecture makes this a conservative local reference. A
release target receives its own baseline before support promotion.

## Results

Medians from the five samples:

| Operation | Median | Allocations |
| --- | ---: | ---: |
| Canonical remote logical path | 711 ns/op | 832 B, 9 allocs/op |
| Authenticated loopback API read middleware | 717 ns/op | 1,856 B, 14 allocs/op |
| Verified atomic 1 MiB APFS install | 8.58 ms/op, 122.22 MB/s | 133,956 B, 30 allocs/op |

The install benchmark includes sibling temporary-file creation, SHA-256,
permission application, file flush, atomic no-replace rename, and directory
flush. It intentionally measures durability rather than buffered write speed.

## Budgets

Until a target-specific baseline replaces them, changes fail performance review
when the median of five comparable samples exceeds any of these bounds:

- canonical logical path: 2 microseconds and 16 allocations;
- authenticated local API read middleware: 2 microseconds and 24 allocations;
- verified 1 MiB install on a supported local filesystem: below 75 MB/s; or
- any unbounded growth in allocations as path length or request count rises.

The Phase 2 reference-hardware gate for a 100,000-file metadata-only scan is:

- complete within 30 seconds after filesystem caches are warm;
- peak Go heap at or below 512 MiB;
- bounded catalog pages of at most 4,096 records; and
- observe cancellation within 2 seconds without losing the last durable
  checkpoint.

That scan budget is frozen here but remains unproven until the Phase 2 scanner
exists. Transfer, Fylo repository, Fyne startup, and S3 provider baselines are
recorded by their own qualification slices and are not inferred from these
numbers.

## Maintained packaged topology baseline

The unsigned arm64 `Sluice.app` was staged from Sluice source revision
`8f7da959bc5a6945cab698ddb8f7af8c907f9abe`. The maintained run used the real
desktop, Tachyon, agent, and Fylo processes with a restricted `PATH`, waited 30
seconds before sampling, then observed one unchanged healthy process generation
for 600 seconds. There was no automatic replacement during warmup or the
sustained post-warmup sample; the later recovery measurements were separately
forced after idle sampling completed.

| Measurement | Result |
| --- | ---: |
| Authenticated startup | 869 ms |
| Idle warmup | 30 s; no recovery |
| Sustained idle sample | 600 s; 61 samples |
| Aggregate CPU from process time | 0.855% |
| Agent CPU from process time | 0.002% |
| Agent plus Fylo CPU from process time | 0.002% |
| Sampled aggregate CPU, mean / max | 0.577% / 1.500% |
| All-process RSS, mean / max | 106,599 KiB / 186,256 KiB |
| Desktop plus agent RSS, mean / max | 95,751 KiB / 172,528 KiB |
| Authenticated recovery after Tachyon `TERM` | 480 ms |
| Authenticated recovery after agent `KILL` | 372 ms |
| Clean shutdown | 59 ms |

The desktop survived both forced faults. For each fault the coordinator retired
the prior agent/Tachyon/Fylo generation, started a complete replacement, waited
for authenticated health, and rotated the private IPC capability. The stable
API token and Fylo root were preserved. This proves bounded supervisor recovery
separately from the stable idle generation; it does not disguise spontaneous
replacement as healthy idle behavior.
