# Agent IPC Qualification: macOS arm64, 2026-08-21

## Result

The Phase 1 agent-bridge and durable mutation contract passed on the named
host. A real Tachyon 26.33.02 server invoked the compiled `sluice-yon`
executable, which forwarded requests over the bounded authenticated IPC
protocol to a real `sluice-agent` process. That agent owned a warm Fylo
26.33.02 child and its exclusive root.

After one mutation response was durably recorded, the agent and Fylo child
were stopped and restarted on the same root. Retrying the same request through
Tachyon returned the recorded response; reusing the key with a different body
returned the stable `idempotency_key_reused` conflict.

This evidence qualifies the bridge on this host only. Windows and Linux native
execution remain separate gates.

## Qualified contract

- IPC listens only on an explicit loopback address.
- Every agent start creates a fresh 256-bit session capability.
- The private mode-0600 descriptor separates IPC authority from the local API
  bearer credential.
- Agent frames are newline-delimited JSON, protocol-versioned, and bounded to
  1 MiB requests and 4 MiB responses.
- Authorization and idempotency headers survive the Yon-to-agent bridge.
- Wrong session capabilities, protocol mismatches, oversized requests, and an
  unavailable agent fail closed with stable classifications.
- Connection admission is bounded. Shutdown prevents new worker admission,
  cancels active handler contexts, releases a saturated accept loop, and waits
  for admitted workers to finish.
- The persistent agent owns state startup and shutdown; it publishes the
  descriptor only after state starts and removes its own descriptor on clean
  shutdown.
- Duplicate mutations are replayed only when a supplied idempotency store has
  recorded the result.
- The production `sluice-agent` supplies the Fylo-backed idempotency store.
  Each accepted key is hashed and reserved in the `idempotency` collection
  before application code runs. Completed status, headers, and body are
  persisted for replay; the bearer token and raw key are not stored.
- An interrupted pending reservation fails closed on retry instead of deleting
  the reservation and possibly repeating an uncertain side effect.
- Real `createCollection`, `putData`, `findDocs`, and `patchDoc` operations
  wrote and replayed an application response across a Fylo supervisor restart.
- Real `queuePublish`, `queueClaim`, and `queueAck` operations proved durable
  recovery: an unacknowledged lease expired across owner restart, was delivered
  at attempt two with a new fenced receipt, and disappeared after ACK.
- Tachyon registration passes the session descriptor as a direct argument
  vector. No shell interprets the executable or its arguments.

## Remaining integration gates

- Repeat the contract and race suites natively on Windows and Linux.
- A pending reservation deliberately remains fail-closed because the Phase 1
  local API has no operator-facing inspection or resolution route yet. Phase 2
  must connect mutations to the durable operation ledger so recovery can
  finish or explicitly resolve an uncertain result.
- The production application currently exposes only `GET /v1/health`; the
  four-process mutation test records its bounded not-found response. Enabling
  a domain mutation requires its own operation-ledger and side-effect recovery
  contract, but no command-wiring or idempotency-store gap remains.
- The production topology uses authenticated loopback TCP for its portable
  Phase 1 contract. A later ADR may promote Unix-domain sockets and Windows
  named pipes without changing the versioned envelope.
