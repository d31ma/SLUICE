# Garage Provider Qualification Attempt - 2026-08-21

## Result

Garage v2.3.0 failed Sluice's required provider contract because its capability
probe rejected conditional object creation. Range downloads, multipart
uploads, and SHA-256 reporting passed the probe; object versioning was also
unavailable.

```text
provider=Garage v2.3.0 capabilities={ConditionalWrites:false RangeDownloads:true MultipartUploads:true ObjectVersioning:false ChecksumSHA256:true}
provider Garage v2.3.0 lacks required core capability
```

The exact image was
`dxflrs/garage@sha256:866bd13ed2038ba7e7190e840482bc27234c4afaf77be8cfa439ae088c1e4690`
on Linux arm64. The service was single-node, isolated, and bound to loopback.

The failure is an expected compatibility determination, not a Garage defect.
Sluice's manifest protocol requires conditional creation and compare-and-swap
to prevent silent overwrite. A provider that lacks that behavior cannot be
enabled for synchronization.

The temporary Garage bucket and access key were deleted, the named container
was stopped and removed, and its scratch directories were moved to Trash.
